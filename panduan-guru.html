1

Ringkasan & cakupan

Apa yang dibangun, untuk siapa, dan apa yang sengaja tidak termasuk.

Aplikasi adalah laboratorium jaringan visual untuk siswa SMA/SMK kelas X yang belum memiliki pengetahuan jaringan. Siswa menyusun perangkat, menghubungkannya, memberi alamat IP, memvalidasi topologi, lalu mengirim paket dan membaca perjalanannya langkah demi langkah.

Tujuan pembelajaran yang didukung

KonsepBentuk di aplikasiBukti pemahaman
Perangkat jaringanKomputer, laptop, ponsel, server, switch, access point, router, internet.Siswa memilih perangkat yang tepat untuk peran tertentu.
Topologi LANKabel Ethernet dan tautan Wi-Fi pada kanvas.Semua perangkat terhubung; endpoint menuju switch/AP; switch/AP menuju router.
Peran routerRouter menjadi penghubung jaringan lokal ke Internet.R06 dan R07 lolos; narasi hop menyebut penerusan paket.
Access pointTautan nirkabel ke laptop/ponsel dan kabel ke router.R05 lolos untuk perangkat nirkabel; simulasi memakai hop Wi-Fi.
Pengalamatan IPBidang IP pada panel Info tiap perangkat.R08 (lengkap) dan R09 (unik) opsional.
Rute paketAnimasi hop, panel narasi, ringkasan jumlah perangkat.Siswa menjelaskan urutan dan fungsi tiap perangkat.

Yang sudah tersedia

Fitur inti

  • Kanvas dengan 8 jenis perangkat.
  • Tautan kabel dan nirkabel.
  • Ubah nama dan IP perangkat.
  • Validasi 7 aturan wajib + 2 pemeriksaan IP opsional.
  • Simulasi paket dengan narasi per hop.
  • Dua skenario siap pakai dan reset.
  • Zoom, pan, dan status bar.

Kenyamanan pengajaran

  • Antarmuka penuh Bahasa Indonesia.
  • Tanpa instalasi, akun, atau internet.
  • Satu file, mudah dibagikan.
  • Pesan kesalahan spesifik dan suportif.
  • Bisa dicetak/ditampilkan di proyektor.
  • Bisa dimodifikasi dengan editor teks.

Batasan yang perlu diketahui guru

Simulasi ini bersifat logis, bukan emulasi jaringan nyata. Aplikasi tidak menjalankan protokol TCP/IP, tidak melakukan DNS lookup, tidak menghitung latency atau packet loss, dan tidak memeriksa subnet mask, gateway, atau format IPv4. Validasi IP hanya memeriksa kosong/tidak dan duplikat. Ajarkan format dan konsep subnet secara terpisah.
  • Tidak ada penyimpanan otomatis. Memuat ulang halaman menghapus seluruh pekerjaan.
  • Tidak ada ekspor gambar/PDF bawaan. Gunakan tangkapan layar atau cetak halaman browser.
  • Tidak ada kuis, login, atau rekap nilai. Penilaian dilakukan guru dengan rubrik di bagian 10.
  • Tidak ada DNS, DHCP, NAT, atau subnetting. Cocok untuk pengenalan topologi dan alamat IP dasar.
  • Bukan untuk ponsel. Di bawah 1024 px aplikasi menampilkan banner; gunakan laptop/PC.
  • Tautan selalu dua arah. Tidak ada konsep arah kabel atau VLAN.

Langkah membuka

  1. Ekstrak atau salin folder yang berisi index.html ke komputer.
  2. Klik dua kali index.html. Browser default akan membukanya sebagai file:///....
  3. Jika terbuka di editor teks, klik kanan → Open with → Chrome/Edge/Firefox.
  4. Pastikan kanvas, panel kanan, dan toolbar tampil. Aplikasi siap dipakai.
Mengapa aman dibuka langsung? Seluruh CSS, JavaScript, dan ikon ditulis di dalam file. Tidak ada Google Fonts, CDN, gambar eksternal, atau API. Jika sekolah memblokir internet, aplikasi tetap berjalan penuh.

Cara membagikan ke siswa

Paling sederhana

  • Kirim satu file index.html melalui Google Classroom, Teams, atau LMS.
  • Siswa mengunduh, lalu membukanya di browser.
  • Panduan guru tidak perlu dibagikan ke siswa.

Lab komputer

  • Salin file ke setiap komputer atau folder bersama.
  • Buat pintasan di desktop agar mudah ditemukan.
  • Tidak perlu hak administrator.

Tab panel kanan

Info

  • Saat belum ada perangkat: petunjuk menyeret perangkat.
  • Saat perangkat dipilih: nama, jenis, IP, tombol Jadikan Sumber dan Jadikan Tujuan.
  • Perubahan nama/IP langsung terlihat di kanvas.

Validasi

  • Tombol Periksa Jaringan.
  • Skor wajib x/7 dan status opsional IP.
  • Daftar 9 aturan dengan status lulus/gagal dan pesan perbaikan.

Simulasi

  • Ringkasan sumber dan tujuan.
  • Tombol Kirim Paket / Kirim Ulang, Hentikan.
  • Kartu narasi per hop dan ringkasan akhir.

Umpan balik

  • Toast muncul singkat di bawah untuk konfirmasi/kesalahan.
  • Dialog konfirmasi muncul saat memuat skenario atau reset jika kanvas berisi perangkat.
  • Banner mobile muncul di layar sempit.

Membaca status dan petunjuk

  • Siap — belum ada masalah atau validasi belum dijalankan.
  • Siap · 7/7 — validasi terakhir lulus semua aturan wajib.
  • Ada masalah — masih ada aturan wajib yang gagal; skor rinci terlihat di tab Validasi.
  • Zoom — persentase tampilan kanvas; skenario otomatis di-fit saat dimuat.
  • Petunjuk bawah — berubah sesuai konteks, misalnya “Klik dua kali perangkat untuk mengubah nama & IP.”
Untuk proyektor: gunakan zoom 100–125% agar label dan IP terbaca. Jika topologi melebar, gunakan Space + seret atau klik tengah untuk pan, bukan mengecilkan sampai tidak terbaca.

Perilaku umpan balik

  • Toast tampil ± 3,4 detik di bawah kanvas. Warna hijau untuk sukses, merah untuk kesalahan, netral untuk informasi.
  • Konfirmasi memakai dialog browser, bukan dialog kustom. Teksnya: “Reset canvas dan muat skenario ini?” atau “Reset canvas? Semua perangkat dan koneksi akan dihapus.”
  • Status bar berubah menjadi Mengirim paket… saat animasi berjalan, lalu Siap · 7/7 atau Ada masalah setelah validasi.
  • Validasi lama dihapus saat perangkat, tautan, nama, atau IP diubah. Jalankan ulang validasi setelah perbaikan.
Jangan mengandalkan klik kanan. Aplikasi tidak memiliki menu konteks khusus. Semua aksi ada di toolbar, panel, atau melalui klik dua kali. Jika ragu, kembali ke alat Pilih dengan V.

Gunakan pola Lihat → Tiru → Bangun → Jelaskan. Siswa perlu melihat satu rute yang benar sebelum membangun sendiri, lalu menjelaskan alasannya dengan kata-kata sendiri.

Alur kerja siswa (poster ringkas)

  1. Susun perangkat. Seret dari palet. Mulai dari Internet → Router → Switch/AP → endpoint.
  2. Hubungkan. Gunakan Kabel untuk backbone dan Nirkabel untuk laptop/HP ke AP. Cek tidak ada perangkat yatim.
  3. Beri identitas. Klik dua kali perangkat; isi nama yang bermakna dan IP unik. Internet tidak diberi IP.
  4. Validasi. Buka tab Validasi. Baca aturan yang gagal, perbaiki satu per satu, lalu periksa ulang.
  5. Simulasikan. Tandai sumber dan tujuan. Kirim paket. Baca setiap kartu narasi, bukan hanya pesan sukses.
  6. Jelaskan. Minta siswa menutup panel dan menceritakan rute dari ingatan.
Aturan emas saat demonstrasi: selalu validasi sebelum simulasi. Ini membiasakan siswa memeriksa topologi, bukan menebak-nebak. Jika simulasi gagal, arahkan ke tab Validasi terlebih dahulu, bukan langsung mengubah kabel.

Variasi kegiatan

Demo interaktif

  • Proyeksikan aplikasi; siswa memberi instruksi (“tambah router”, “hubungkan PC-03”).
  • Guru sengaja salah memilih alat untuk memancing koreksi.
  • Minta siswa memprediksi warna hop dan label berikutnya.

Kerja berpasangan

  • Siswa A membangun, siswa B memvalidasi dan mencatat aturan yang gagal.
  • Setelah 10 menit, tukar peran dan muat ulang skenario.
  • Pasangan lain mengecek rute dengan simulasi.

Lab komputer

  • Satu siswa per komputer; simpan file di folder yang mudah diakses.
  • Minta siswa tidak menutup tab sampai presentasi selesai.
  • Siapkan skenario cadangan jika ada siswa yang tertinggal.

Kelas tanpa lab

  • Guru mendemonstrasikan, siswa menggambar topologi di buku.
  • Siswa menuliskan narasi hop berdasarkan apa yang dilihat.
  • Gunakan tangkapan layar sebagai bahan kuis tertulis.

Pertanyaan pemandu

  • Mengapa komputer tidak langsung dihubungkan ke Internet tanpa router?
  • Apa perbedaan peran switch dan access point?
  • Mengapa laptop dan HP pada skenario rumah terhubung ke AP, bukan ke router?
  • Apa yang terjadi jika satu kabel backbone dihapus? Aturan mana yang gagal?
  • Mengapa dua perangkat tidak boleh memakai IP yang sama?
  • Jika ada dua jalur, jalur mana yang dipilih aplikasi? (Jalur terpendek berdasarkan jumlah hop.)

Dua latihan siap pakai, lengkap dengan nilai awal dan hasil yang diharapkan.

Kedua skenario dimuat dari menu Muat Skenario. Saat dimuat, aplikasi menghapus simulasi dan validasi lama, mengosongkan pilihan sumber/tujuan, berpindah ke tab Info, lalu auto-fit kanvas ke seluruh perangkat (zoom 45%–125% tergantung ukuran layar).

Konfirmasi: jika kanvas sudah berisi perangkat, muncul pertanyaan “Reset canvas dan muat skenario ini?”. Jika dibatalkan, kanvas tidak berubah. Jika kanvas kosong, skenario langsung dimuat.

Validasi bukan jaminan konektivitas end-to-end. Aturan memeriksa keberadaan komponen dan hubungan lokal, bukan apakah seluruh perangkat berada dalam satu komponen terhubung. Contoh: Internet–Router–Switch–PC-01 di satu sisi, dan Switch-2–PC-02 di sisi lain, dapat memperoleh 7/7 karena setiap syarat terpenuhi secara terpisah. Selalu jalankan simulasi dari endpoint ke Internet untuk membuktikan jalur. Ini juga bisa dijadikan tantangan “cari celah validasi” untuk siswa lanjutan.

Hal yang tidak diperiksa

  • Format IPv4. “abc”, “999.999.999.999”, atau “192.168.1” diterima sebagai string.
  • Subnet mask, gateway, DNS, DHCP. Tidak ada konsep ini di aplikasi.
  • Kelas IP, private/public, atau rentang yang benar. Tidak divalidasi.
  • Kesamaan segmen jaringan. 10.0.0.1 dan 192.168.1.10 dianggap unik dan valid.
  • Konektivitas penuh. Gunakan simulasi untuk memastikan jalur benar-benar tersambung.
  • Kesesuaian jenis kabel. R05 tidak membedakan kabel/nirkabel; AP dan switch diperlakukan sama untuk syarat ini.
Untuk penilaian pengalamatan IP, jangan cukup melihat 7/7. 7/7 dapat dicapai dengan semua IP kosong. Tetapkan kriteria tambahan: 7/7 + 2/2 dan periksa format IP secara manual, atau minta siswa menjelaskan aturan IP yang mereka pakai.

Kapan harus memvalidasi ulang?

Setiap kali perangkat ditambah/dihapus, tautan dibuat/dihapus, nama diubah, atau IP diubah, hasil validasi lama otomatis dihapus. Klik Periksa Jaringan lagi. Memindahkan perangkat di kanvas tidak mengubah topologi, jadi hasil validasi tetap berlaku.

Simulasi paket

Cara menandai endpoint, membaca animasi, dan menafsirkan narasi.

Menyiapkan sumber dan tujuan

  1. Pilih perangkat di kanvas, lalu buka tab Info.
  2. Klik Jadikan Sumber. Perangkat mendapat lencana S.
  3. Pilih perangkat lain, klik Jadikan Tujuan. Perangkat mendapat lencana D.
  4. Alternatif cepat: Shift+klik perangkat pertama, lalu Shift+klik perangkat kedua.
  5. Buka tab Simulasi dan klik Kirim Paket.
Aturan endpoint: sumber dan tujuan harus dua perangkat berbeda. Menetapkan perangkat yang sama untuk peran lain akan mengosongkan peran sebelumnya. Menekan tombol peran yang sama sekali lagi akan membatalkan peran tersebut. Semua jenis perangkat, termasuk Internet dan Server, boleh menjadi sumber/tujuan.

Rute 3 hop biasanya selesai dalam ± 4–6 detik. Nilai ini tidak dapat diubah dari antarmuka; ubah kode jika perlu (lihat bagian 11).

Rute dan pemilihan jalur

  • Aplikasi memakai BFS (Breadth-First Search) pada graf tak berarah, sehingga memilih jalur dengan jumlah hop paling sedikit.
  • Jika ada beberapa jalur terpendek, jalur yang ditemukan lebih dulu berdasarkan urutan tautan yang menang. Urutan ini tidak terlihat oleh siswa.
  • Jumlah perangkat pada ringkasan = panjang jalur, termasuk sumber dan tujuan. Jumlah hop = jumlah perangkat − 1.
  • Tautan kabel dan nirkabel dianggap sama untuk pencarian jalur; jenisnya hanya memengaruhi teks narasi.
  • Perangkat terisolasi atau “pulau” terpisah menghasilkan Tidak ada jalur.

Cara menafsirkan hasil bersama siswa

  • Jangan berhenti di pesan sukses. Minta siswa menyebutkan urutan perangkat dan jenis tautan tiap hop.
  • Tanyakan fungsi tiap perangkat, bukan hanya namanya: switch meneruskan dalam LAN, router menghubungkan ke WAN, AP menjembatani Wi-Fi.
  • Bandingkan dua rute: PC-01 → Internet dan Laptop → Internet. Apa peran AP yang tidak dimiliki Lab?
  • Saat gagal, bedakan dua penyebab: topologi (tidak ada jalur) dan aturan (validasi gagal). Jalankan validasi untuk mempersempit.
  • Minta siswa memprediksi narasi hop berikutnya sebelum animasi mencapainya.
Diskusi multi-jalur: buat tautan tambahan antara Switch Lab dan AP Wi-Fi. Rute PC-01 → Internet tetap 3 hop; rute PC-04 → Internet juga 3 hop. Jika ada dua jalur sama panjang, siswa tidak dapat menebak dari tampilan—jelaskan bahwa aplikasi memilih yang ditemukan lebih dulu.

Jika aplikasi benar-benar tidak dapat dibuka

  1. Pastikan file berekstensi .html, bukan .txt atau .htm.txt.
  2. Klik kanan → Open with → pilih browser, atau seret file ke jendela browser.
  3. Coba mode incognito untuk menyingkirkan ekstensi yang agresif.
  4. Salin ulang file dari sumber asli; bandingkan ukurannya (± 90 KB).
  5. Jika masih gagal, buka konsol dan catat pesan error pertama; biasanya menunjuk baris yang bermasalah setelah kustomisasi.
Jangan mengubah state melalui console saat mengajar. Aplikasi tidak menyediakan API publik; manipulasi langsung dapat membuat tampilan dan data tidak sinkron. Gunakan antarmuka yang tersedia.

Privasi & keamanan

  • Tidak ada data keluar. Tidak ada fetch/XHR, analytics, atau telemetry.
  • Tidak ada akun. Tidak ada login, email, atau identitas siswa.
  • Tidak ada penyimpanan persisten. Semua data hilang saat tab ditutup.
  • Tidak ada input berbahaya. Nama dan IP di-escape sebelum dirender ke SVG/HTML.
  • Aman untuk lab sekolah yang membatasi internet; aplikasi berjalan offline penuh.

Aksesibilitas

  • Toolbar memakai aria-label, aria-pressed, dan judul pintasan.
  • Tab memakai role="tab", aria-selected, aria-controls.
  • Panel hasil validasi dan simulasi memakai aria-live untuk pembaca layar.
  • Kartu palet dapat difokuskan dengan Tab dan diaktifkan dengan Enter/Space.
  • Navigasi keyboard untuk memindahkan perangkat tidak disediakan; gunakan mouse/trackpad.

Catatan pemeliharaan

  • Sumber kebenaran perilaku adalah index.html versi ini. Dokumen spesifikasi menjelaskan maksud desain; jika berbeda, ikuti implementasi dan catat penyimpangan (misalnya AP pada Skenario 2).
  • Jika mengubah aturan wajib, perbarui angka 7/7 di panduan, rubrik, checklist, dan komunikasi ke siswa.
  • Jika mengubah skenario, perbarui tabel perangkat/tautan dan hasil yang diharapkan di bagian 7.
  • Jika mengubah teks narasi, perbarui tabel pola narasi di bagian 9.
  • Jika mengubah timing, perbarui perkiraan durasi di bagian 9.
  • Uji ulang setelah perubahan: kedua skenario, validasi, simulasi sukses, simulasi tanpa jalur, reset, duplikat tautan, dan IP duplikat.
